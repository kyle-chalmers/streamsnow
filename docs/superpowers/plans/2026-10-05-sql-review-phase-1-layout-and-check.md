# SQL review redesign, phase 1: layout and offline check

Spec: `docs/superpowers/specs/2026-10-04-sql-review-redesign.md` (decisions 1-6, 8-11, 13).
One PR, releasable on its own. Version 0.7.6 → **0.8.0** (breaking: old `sql_review/` format
removed with no migration, decision 11).

## Goal

Every scaffolded app has `apps/<slug>/sql_review/` laid out as:

```
sql_review/
  AGENTS.md                         folder rules (tool-owned template, human-editable below marker)
  CLAUDE.md                         @AGENTS.md
  README.md                         human index; tables between markers are generated
  index.yaml                        single source of truth (hand-edited)
  01_overview.sql                   one file per page, NN = page order from app_nav
  02_<page>.sql
  app_specific_reporting_objects/
    <db>.<schema>.<object>.sql      maintained DDL, one file per object
```

`streamsnow sql-review generate` builds page files, README tables and DDL "Used by" lines from
`index.yaml`; `streamsnow sql-review check` verifies everything offline.

## Out of this phase

`probe`, `run`, `bench`, `compare`, `log`, agents, the `/sql-review` skill (phase 2), screen
capture writing files (phase 3; this phase ships `review_value` as a no-op plus the env-flag
plumbing only).

## Task 1: `index.yaml` schema and loader

New module `streamsnow/tools/sql_review_index.py` (keep `sql_review.py` the CLI and verbs; it is
already 2255 lines).

```yaml
schema_version: 2
app: <slug>
review_window:            # applied as a per-section params CTE (decision 2)
  start_date: "DATEADD(day, -30, CURRENT_DATE())"
  end_date: "CURRENT_DATE()"
pages:
  - path: pages/overview.py          # must match an app_nav entry; order comes from app_nav
    metrics:
      - key: total_revenue           # stable key, snake_case, <=5 words
        query: queries/total_revenue.sql
        tokens: {REGION: "'West'"}   # sample values for {UPPERCASE} tokens
        binds: {start_date: params.start_date}
        notes: "Excludes refunds; booked date, not ship date."
        reads: [ANALYTICS.REPORTING.APP_REVENUE_DAILY]
objects:                             # app-specific reporting objects
  - name: ANALYTICS.REPORTING.APP_REVENUE_DAILY
    grants: [ROLE_APP_READER]
```

- Dataclasses `Index`, `Page`, `Metric`, `ReportingObject`; `load_index(app_dir) -> Index`.
- Validation errors as findings (not exceptions) with kind `index`: unknown keys, duplicate
  metric keys within a page, key not snake_case or more than five words, page path not found by
  `app_nav.extract_nav`, query file missing, token in query without a sample value, unused token.
- Metric position numbers are **derived**, never stored: order within `metrics:` = on-screen
  order (decision 3). Page numbers come from `app_nav` order, not from the YAML order; a YAML
  page missing from nav is a finding.
- Uses `yaml.safe_load` (pyyaml is already a runtime dep).

Tests: `tests/test_sql_review_index.py`. Valid file round-trip; each validation finding;
renumbering when nav order changes; page in nav but absent from index → finding (coverage).

## Task 2: page file renderer (`generate`)

Rewrite `render_*` in `sql_review.py`; delete manifest, combo, metrics-mode, `_metrics/` and
token-strategy code (`load_manifest`, `_validate_*`, `_resolve_token`, `_import_modules`,
`render_review_file`, `render_metrics_file`, `cmd_discover`, `cmd_index` and their helpers).
Keep and reuse: masking (`_mask_strings_and_comments`), `_split_statements`, `_verify_read_only`,
`_WRITE_VERBS`, `_lf`, bind detection (`_BIND_RE`), `_TOKEN_RE`.

Output `NN_<page_stem>.sql` (NN two-digit nav order, stem from page path, snake_case):

```
-- Page: Overview (pages/overview.py)
-- App: <slug>   Review window: last 30 days (edit params CTE per section)
-- Generated by `streamsnow sql-review generate` from index.yaml. Do not edit; edit index.yaml
-- or queries/*.sql and regenerate.
-- Metrics: 1 total_revenue, 2 orders_by_region
...                                     (header padded so line 9 is the first tag, see below)
--1_total_revenue
WITH params AS (
    SELECT DATEADD(day, -30, CURRENT_DATE()) AS start_date, CURRENT_DATE() AS end_date
),
...
SELECT ...;

--2_orders_by_region
WITH params AS (...)
...
```

Rules:
- Tag line `--N_key` alone on the line directly above the section SQL; no blank line between
  them. For metric 1 the header is fixed-height so the tag is line 9 and the SQL starts line 10
  (Kyle's stated format). Assert this in a test.
- Each section is self-contained and runnable on its own: `:name` binds and `{TOKENS}` from the
  app query are replaced by `params.<name>` references / sample literals; a `params` CTE is
  prepended (merged into an existing leading `WITH`). No file-level `SET`.
- Exactly one `;` per section; one blank line between sections.
- Keep the provenance footer (`-- Provenance: schema=2 inputs=… output=…`), with
  `GENERATOR_SCHEMA = 2` and inputs = index.yaml + referenced queries.
- Run sqlfluff `fix` on each section before stamping (Task 5). Lint the body only, not the
  header or tag lines.
- Read-only guard runs on the rendered output, as today.

Tests: line-9/line-10 invariant; section runnable in isolation (parse each section, assert it
starts with `WITH params`); token and bind substitution; leading-`WITH` merge; reorder metrics →
renumbered tags and file names; stale `NN_*.sql` from a renamed page removed by `generate` and
reported by `check` as orphan.

## Task 4: `app_specific_reporting_objects/` (decisions 6, 7)

- One file per object, named `<DB>.<SCHEMA>.<OBJECT>.sql`, header:

  ```
  -- Object: ANALYTICS.REPORTING.APP_REVENUE_DAILY
  -- Purpose: <one line>
  -- Used by: 01_overview.sql #1 total_revenue; 02_regions.sql #2 orders_by_region   (generated)
  -- Grants: ROLE_APP_READER
  -- Applied by a human. Claude deploys only when explicitly asked.
  CREATE OR REPLACE VIEW ...
  ```

- `generate` rewrites only the `Used by:` line (from index `reads:`); everything else is
  hand-maintained DDL.
- `check` rules (kind `objects`): every DDL file referenced by ≥1 metric `reads:`; every
  `objects:` entry has a DDL file and vice versa; `Object:` header equals file name; header
  fields present.
- Exempt from the read-only guard; never executed by any review verb.

## Task 5: sqlfluff lint (decision 9)

- Add `sqlfluff` to runtime deps in `pyproject.toml` (generate needs it, not only dev); `uv lock`.
- One repo-level config, `_templates/repo/sqlfluff.j2` → `<repo>/.sqlfluff`: dialect
  `snowflake`, max line length 100, keywords upper, identifiers as-is. Page files lint with the
  `raw` templater (they contain no placeholders). App `queries/*.sql` contain `:bind` and
  `{TOKENS}`: lint them with `templater = placeholder`, `param_style = colon`, after
  pre-substituting `{TOKENS}` with their index sample values. Verify both on the scaffold.
- Use the Python API (`sqlfluff.fix` / `sqlfluff.lint`), not a subprocess.
- `check` runs lint on page files and on the app's `queries/*.sql`; findings kind `lint` with
  rule code and line.
- Measure: lint time for the scaffolded app; if `check` in the pre-commit hook exceeds ~2 s,
  lint only staged files there and everything in CI.

## Task 6: comment rules (decision 10)

`check` findings kind `comments`, applied to app `queries/*.sql` (the source of the page
sections):
- every CTE has a `--` comment line directly above its `name AS (`;
- every comment line ≤ 100 characters;
- comment lines / (comment + SQL lines) ≤ 25% per query (warn-level: put in `advisory`, not
  correctness).
"Never restate the SQL" and "one per 5-10 lines" are judgment calls for the phase-2 page
reviewer, not machine checks. Document that split in sql_review AGENTS.md.

## Task 7: `check` rewrite

`index.yaml: fragments:`). Keep `--format md|json`, exit codes 0/1/2, and `coverage_policy`
(`sql_review.coverage` in config) as is.

Fix the known issue: a freshly scaffolded app must pass `check` without a manual `generate`
